# 卡片规范详解

> Core Schema + Profile 是如何定义一张知识卡片的。

## 卡片的两层结构

每张知识卡片由两部分组成：

**Metadata（元信息）**：卡片的"信封"——标识、分类、版本追踪。
**四个槽位（Learning Slots）**：卡片的"内容"——知、解、联、验。

### Metadata 字段

| 字段 | 必填 | 说明 |
|------|------|------|
| `id` | ✅ | 唯一标识符（格式：`profile-slug`，如 `ai-tech-embedding`） |
| `title` | ✅ | 知识点名称 |
| `profile` | ✅ | 使用的 Profile（如 `ai-tech`、`language`、`general`） |
| `schema_version` | ✅ | Core Schema 版本号 |
| `profile_version` | ✅ | Profile 版本号 |
| `category` | ⚙️ | 由 Profile 决定是否必填 |
| `tags` | ❌ | 自由标签 |
| `created` | ✅ | 创建时间（自动生成） |
| `updated` | ✅ | 最后更新时间（自动生成） |
| `source` | ❌ | 知识来源 |

### 四个学习能力槽位

| 槽位 | 英文 | 核心问题 |
|------|------|----------|
| **知** | KNOW | 这个知识是什么？ |
| **解** | UNDERSTAND | 我如何理解它？ |
| **联** | CONNECT | 它和什么有关？ |
| **验** | VERIFY | 我怎么证明自己会了？ |

四个槽位是骨架，Profile 决定每个槽位里放什么字段。槽位允许留白——不要为了填满而硬凑内容。

## 卡片文件格式

卡片是 **Markdown 文件**，使用 YAML frontmatter 存储 Metadata：

```markdown
---
id: ai-tech-embedding
title: Embedding
profile: ai-tech
schema_version: "0.1"
profile_version: "0.1"
category: AI与数据科学
tags: [向量, NLP]
created: 2026-08-17
updated: 2026-08-17
---

## KNOW · 知识本体

（Profile 定义的字段内容）

## UNDERSTAND · 理解方式

（Profile 定义的字段内容）

## CONNECT · 知识关联

（Profile 定义的字段内容）

## VERIFY · 学习验证

（Profile 定义的字段内容）
```

## Profile 如何影响卡片

同一个概念，用不同 Profile 生成的卡片，内容完全不同：

- `ai-tech` Profile 要求记录英文全称、发音谐音、项目实例
- `language` Profile 要求记录音标、例句、词族
- `general` Profile 只要求最基本的定义、类比、关联

详见 [Profile 接口规范](../profiles/README.md) 和完整的 [Core Schema 定义](../core/SCHEMA.md)。
