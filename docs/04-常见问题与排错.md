# 常见问题与排错

## 常见问题

### Q: 随手学和 Anki / Obsidian / Notion 有什么区别？

随手学不是笔记软件，也不是闪卡工具。它是一套让 AI 理解"学习应该怎么记录"的规则框架。你可以把它理解为 AI 和你之间关于"怎么存知识"的一份协议。卡片是纯 Markdown 文件，你可以用任何编辑器打开。

### Q: Private 能给好几个人一起用吗？

不能。Private 是单用户多设备：一台服务器对应一个人的一套卡片，所有令牌看到的都是同一套卡片。想给别人用，请让对方部署自己的一套。

### Q: 必须用 Claude 吗？

不是。随手学通过 MCP（Model Context Protocol）与 AI 通信，任何支持 MCP 的 AI 客户端都可以使用。目前主流支持 MCP 的客户端包括 Claude Desktop、Cursor 等。

### Q: 我能不能用 ChatGPT？

可以。ChatGPT 桌面端和 Codex CLI 均已支持 MCP，配置方式和 Claude Desktop 类似，将 MCP 服务器指向 `server.py` 即可。

### Q: 卡片存在哪里？

Lite 模式下，卡片就是你本地文件夹里的 Markdown 文件。你可以用任何文本编辑器打开、编辑、备份。

### Q: 怎么备份？

复制 cards 文件夹即可；也可以使用你信任的版本管理或备份工具定期保存。想要多设备同步和修改历史，可以开启 Pro 的 Git 同步，见 [Pro：同步与展示](05-Pro-同步与展示.md)。

### Q: 开启 Pro 的网站后，我的卡片会被公开吗？

只有 tags 里带 `public` 标签的卡片会被生成网页，其余卡片不会进入网站。但要注意：**私有仓库 ≠ 私有网站**，GitHub Pages 网站通常任何人都能访问，打标签前请确认这张卡片可以公开。

### Q: 能不能只用 Core Schema 不用 Profile？

不能。Core Schema 只定义了四个槽位的含义，不定义具体字段。没有 Profile，AI 不知道 KNOW 槽位里应该写"定义"还是"音标"。你至少需要 `general` Profile。

### Q: 我可以创建自己的 Profile 吗？

可以。详见 [Profile 接口规范](../profiles/README.md) 和 [贡献指南](../CONTRIBUTING.md)。

## 排错

### 问题：AI 看不到 kb_save / kb_get / kb_update / kb_search / kb_guide 工具

检查 AI 客户端的 MCP 配置是否正确。确认 server.py 的路径是绝对路径，Python 3.10+ 环境中已安装 pyyaml 和 mcp。运行 `python healthcheck.py` 查看详细状态。

### 问题：保存卡片时报错 "Profile not found"

确认 `config.yaml` 中的 `profiles_dir` 路径正确，且指向包含 Profile YAML 文件的目录。

### 问题：搜索返回空结果

确认 `config.yaml` 中的 `cards_dir` 路径正确，且目录下有 `.md` 文件。Lite 模式使用简单文本匹配，搜索词需要出现在卡片内容中。

### 问题：kb_sync 返回 not_repo，或 healthcheck 提示"卡片目录不是独立的 Git 仓库"

`cards_dir` 必须是一个独立 Git 仓库的根目录。默认的 `kb-mcp/cards` 位于 suishouxue-open 仓库内部，不能直接用于同步。请按 [Pro 教程](05-Pro-同步与展示.md) 另建一个卡片仓库，并把 `cards_dir` 改成它的绝对路径。

### 问题：kb_sync 返回 fetch_failed / push_failed

先在卡片目录里手动运行 `git push origin main`，看能不能成功。随手学在后台运行，不能弹窗输入密码，所以需要提前配好 SSH key 或 credential helper。如果手动推送也失败，先解决 Git 本身的认证或网络问题。`push_failed` 也可能是别的设备刚推送了新内容，再同步一次即可。本地提交在这两种情况下都会保留。

### 问题：kb_sync 返回 conflict

两台设备改了同一张卡片。随手学已取消合并，本地卡片没有被改动。按 [Pro 教程的「处理冲突」](05-Pro-同步与展示.md#处理冲突) 手动解决后再同步。

### 问题：build_site.py 提示缺少 markdown-it-py

运行 `pip install -r requirements-pro.txt`。只有生成网站需要这个依赖，Lite 和 Git 同步不需要。

### 问题：build_site.py 拒绝写入输出目录

生成器只会覆盖空目录或它自己生成过的站点目录，以免误删文件。请换一个新的输出目录。

### 问题：Private 启动时提示"没有可用的访问令牌"

这是设计如此：没有有效令牌时服务拒绝启动。先运行 `python auth_tokens.py create <设备名>`，Docker 部署则运行 `docker compose run --rm suishouxue python kb-mcp/auth_tokens.py create <设备名>`，然后再启动。

### 问题：Private 启动时提示"拒绝监听非本机地址"

本程序不处理 HTTPS，所以默认只监听本机。如果已经把它放在 HTTPS 反向代理后面，并且需要监听 `0.0.0.0`（例如在容器里），设置 `SUISHOUXUE_HTTP_ALLOW_REMOTE_BIND=true`。`deploy/docker-compose.yml` 已经这样配置好了。

### 问题：Private 返回 401

令牌缺失、写错，或者已经被吊销。确认请求头格式是 `Authorization: Bearer ssx_...`，并用 `auth_tokens.py list` 查看该设备的令牌是否仍然有效。

### 问题：Private 返回 421 Misdirected Request

请求的 Host 不在允许列表里。把你的域名加到 `http.allowed_hosts`（或 `SUISHOUXUE_ALLOWED_HOSTS`）。Docker 部署会自动使用 `deploy/.env` 里的 `SUISHOUXUE_DOMAIN`。

### 问题：卡片内容不完整

检查对应的 Profile YAML 是否完整定义了四个槽位。允许槽位留白，但 Profile 本身必须为每个槽位定义至少一个字段。
